Idea clave: separación de responsabilidades

Cada archivo hace una sola cosa, lo que hace el código más fácil de leer, probar y modificar:

  • variables.py define (datos fijos)
  • clases.py modela (qué es un tablero y qué puede hacer)
  • funciones.py auxilia (interacción con el usuario y la máquina)
  • main.py orquesta (junta todo en el flujo del juego)

4.1 variables.py — las constantes

DIMENSIONES = 10
BARCOS = [4, 3, 3, 2, 2, 2, 1, 1, 1, 1]
TOTAL_VIDAS = sum(BARCOS)  # 20

AGUA = "~"
BARCO = "B"
TOCADO = "X"
FALLO = "O"
  • DIMENSIONES: tamaño del tablero. Si algún día queremos otro tamaño, solo se cambia aquí.
  • BARCOS: lista de esloras (longitudes). Cada número es un barco: un 4, dos 3, tres 2 y cuatro 1.
  • TOTAL_VIDAS: suma de la lista = 20 casillas de barco que hay que destruir.
  • Símbolos: cada estado de una casilla tiene su carácter. Usar constantes en lugar de escribir "~" por todo el código evita errores y permite cambiar la apariencia en un solo sitio.
SímboloSignificado
~Agua (sin disparar)
BBarco propio
XBarco tocado
ODisparo al agua (fallo)

4.2 clases.py — la clase Tablero

Cada jugador (usuario y máquina) tiene un objeto Tablero con dos matrices:

MatrizQué guardaQuién la ve
tablero_barcosDefensa: sus barcos y los disparos que recibeSu dueño
tablero_disparosAtaque (radar): los disparos que él ha hecho al rivalSu dueño

Las matrices son listas de listas de Python: tablero[fila][columna].

Constructor

class Tablero:
    def __init__(self, id_jugador):
        self.id_jugador = id_jugador
        self.dimensiones = DIMENSIONES
        self.tablero_barcos = [[AGUA for _ in range(DIMENSIONES)] for _ in range(DIMENSIONES)]
        self.tablero_disparos = [[AGUA for _ in range(DIMENSIONES)] for _ in range(DIMENSIONES)]
        self.vidas = TOTAL_VIDAS
  • Cada matriz se crea con una comprensión de listas doble: 10 filas de 10 casillas de agua.
  • vidas es un contador que empieza en 20 y baja cada vez que se toca un barco.
Se usa una comprensión por fila (y no [[AGUA] * 10] * 10) para que cada fila sea una lista independiente; si no, al modificar una casilla cambiaría la misma columna en todas las filas.

colocar_barcos_aleatoriamente() — pasos 1 y 2

Paso 1: vaciar el tablero y preparar los datos

self.tablero_barcos = [
    [AGUA for _ in range(DIMENSIONES)] for _ in range(DIMENSIONES)
]

barcos = sorted(BARCOS, reverse=True)
posiciones_por_eslora = {}

Los barcos se ordenan de mayor a menor: los grandes son los más difíciles de colocar, así que se colocan primero.

Paso 2: calcular todas las posiciones posibles de cada eslora

for eslora in set(barcos):
    posiciones = set()
    for fila in range(DIMENSIONES):
        for col in range(DIMENSIONES - eslora + 1):
            posiciones.add(tuple((fila, col + i) for i in range(eslora)))
    for fila in range(DIMENSIONES - eslora + 1):
        for col in range(DIMENSIONES):
            posiciones.add(tuple((fila + i, col) for i in range(eslora)))
    posiciones_por_eslora[eslora] = list(posiciones)
  • Se recorre cada eslora distinta (set(barcos)), no cada barco: así no se repite el cálculo.
  • Horizontales: el barco puede empezar en las columnas 0 … 10 - eslora → nunca se sale del tablero.
  • Verticales: igual, pero variando la fila.
  • Cada posición es una tupla de coordenadas, por ejemplo ((3, 2), (3, 3), (3, 4)).
  • Se guardan en un set para evitar duplicados: un barco de 1 casilla sería igual en horizontal y en vertical.
Horizontal y vertical cubren las mismas colocaciones que Norte/Sur/Este/Oeste: un barco que «mira al Norte» ocupa las mismas casillas que uno vertical que empieza más arriba.

Paso 3: búsqueda con retroceso (backtracking)

def colocar_siguiente(indice):
    if indice == len(barcos):
        return True

    posiciones = posiciones_por_eslora[barcos[indice]].copy()
    random.shuffle(posiciones)

    for casillas in posiciones:
        if all(self.tablero_barcos[f][c] == AGUA for f, c in casillas):
            for f, c in casillas:
                self.tablero_barcos[f][c] = BARCO

            if colocar_siguiente(indice + 1):
                return True

            # Esta opción impidió completar la flota: deshacerla.
            for f, c in casillas:
                self.tablero_barcos[f][c] = AGUA

    return False

if not colocar_siguiente(0):
    raise RuntimeError("No se ha encontrado una colocación válida para la flota.")

colocar_siguiente(indice) es recursiva y coloca el barco número indice:

  1. Caso base: si ya se han colocado todos los barcos → True.
  2. Se baraja la lista de posiciones del barco para que el resultado sea aleatorio.
  3. Para cada posición se comprueba que todas sus casillas estén libres (all(... == AGUA)). Esto evita solapamientos.
  4. Si cabe, se coloca (casillas con B) y se pasa al siguiente barco.
  5. Si el siguiente barco no cabe en ningún sitio, se deshace la colocación y se prueba otra posición. Esto es el backtracking.
  6. Si se prueban todas las posiciones sin éxito, devuelve False.
¿Por qué backtracking y no «reintentar hasta que salga»? Reintentar al azar no garantiza terminar. Con backtracking cada posición se prueba como máximo una vez por nivel; como el conjunto de posiciones es finito, el método siempre termina.

Disparos y fin de partida en Tablero

recibir_disparo(fila, col)

def recibir_disparo(self, fila, col):
    if self.tablero_barcos[fila][col] == BARCO:
        self.tablero_barcos[fila][col] = TOCADO
        self.vidas -= 1
        return TOCADO
    elif self.tablero_barcos[fila][col] == AGUA:
        self.tablero_barcos[fila][col] = FALLO
        return FALLO
    else:
        return self.tablero_barcos[fila][col]   # ya impactada

Es el tablero defensivo quien recibe el disparo: barco → X y se descuenta una vida; agua → O; ya impactada → devuelve su estado sin cambiar nada.

registrar_disparo y quedan_barcos

def registrar_disparo(self, fila, col, resultado):
    self.tablero_disparos[fila][col] = resultado

def quedan_barcos(self):
    return self.vidas > 0
  • registrar_disparo anota en el radar del atacante lo ocurrido (X u O): cada jugador ve lo que ha descubierto sin ver los barcos rivales.
  • quedan_barcos es la condición de fin de partida: se acaba cuando las vidas llegan a 0.
Un disparo → dos tableros: el tablero del rival llama a recibir_disparo (actualiza su defensa) y el mío a registrar_disparo (actualiza mi radar). Mantener estas dos vistas separadas evita confundir «lo que hay» con «lo que sé».

disparo_maquina(tablero_maquina)

def disparo_maquina(tablero_maquina):
    disponibles = [
        (f, c)
        for f in range(DIMENSIONES)
        for c in range(DIMENSIONES)
        if tablero_maquina.tablero_disparos[f][c] == AGUA
    ]
    return random.choice(disponibles)
  • Se construye la lista de todas las casillas aún sin disparar de su radar.
  • random.choice elige una al azar → la máquina nunca repite disparo.

4.4 main.py — el bucle principal

def jugar():
    mostrar_bienvenida()
    tablero_jugador = Tablero("Jugador")
    tablero_maquina = Tablero("Máquina")
    tablero_jugador.colocar_barcos_aleatoriamente()
    tablero_maquina.colocar_barcos_aleatoriamente()

    turno = "jugador"

    while tablero_jugador.quedan_barcos() and tablero_maquina.quedan_barcos():
        if turno == "jugador":
            ...
        else:
            ...

Flujo de una partida

  1. Se muestra la bienvenida con las reglas.
  2. Se crean los dos tableros y se colocan las flotas una sola vez.
  3. Empieza el usuario (turno = "jugador").
  4. El bucle while se repite mientras ambos jugadores tengan barcos.
Turno del jugador
  1. Imprime los tableros y el marcador de vidas.
  2. Pide coordenadas (si escribe salir, termina).
  3. tablero_maquina.recibir_disparo(...) y tablero_jugador.registrar_disparo(...).
  4. Si TOCADO → mensaje de impacto; si ya no quedan barcos enemigos, fin; si quedan, sigue siendo su turno.
  5. Si FALLO → mensaje de agua y el turno pasa a la máquina.
Turno de la máquina

Mismo proceso con disparo_maquina: si acierta repite, si falla cede el turno.

Fin de partida

Cuando el bucle termina, se comprueba quién se quedó sin barcos y se muestra el mensaje de victoria 🏆 o derrota 💀.

5. Lo más difícil del desarrollo

🔹 La colocación aleatoria de barcos

Fue la parte más compleja: había que validar que las naves no se salieran del tablero y que no se solaparan entre sí, gestionando distintas orientaciones.

Solución: calcular de antemano solo las posiciones que caben en el tablero y usar backtracking para garantizar que siempre se encuentra una colocación válida y que el método termina.

🔹 La sincronización de los tableros duales

Mantener separada la vista real del tablero propio frente al tablero de seguimiento de ataques requirió una lógica limpia para no confundir coordenadas ni estados (agua frente a impacto).

Solución: dos matrices por jugador con responsabilidades claras:

  • tablero_barcos ← lo modifica recibir_disparo (lo que me hacen)
  • tablero_disparos ← lo modifica registrar_disparo (lo que yo hago)
